# 成员配额与交接

单个成员容易包揽全部工作并无限累积上下文，因此给每个成员设定两个独立上限：已完成任务数（默认 5）与累计 Token（默认 2 亿，按 `tokenUsage` 投影四桶求和），仅对新团队生效。达到任一上限后成员进入 `exhausted`（不可逆，只能被追问或移除），在当前任务结束后按固定模板写出交接文档并通知队长；队长改用其他成员或新增成员继续。

## Consequences

- `exhausted` 成员保留会话与名册，可被追问，但不能再 `claim`/`reassign` 新任务；要更多产能必须新增或替换成员，而不是解除超限。
- Token 预算只统计成员子会话累计的四桶用量，不把当前上下文窗口占用当作累计值。
- 旧 `team.json` 缺配额字段视为不限制，避免升级后旧团队被默认配额突然停掉。
